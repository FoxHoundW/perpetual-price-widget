## 1. 开发背景

本项目用于开发一个常驻 Windows 桌面的币安永续合约价格悬浮窗。产品面向需要持续观察合约行情、但不希望长期占用浏览器或完整交易终端的用户。

产品核心不是替代币安官网，也不是缩小版交易终端，而是：

- 用最少的屏幕空间展示用户关心的永续合约。
- 一眼读取交易对、最新成交价和 24 小时涨跌幅。
- 在短时间价格发生显著变化时持续、明确地提醒用户。
- 保持轻量、稳定、可恢复，并兼顾 Windows 原生窗口体验。
- 只读取公开行情，不接触账户和交易权限。

## 2. 产品目标

### 2.1 核心目标

1. 同时支持币安 USDⓈ-M 与 COIN-M 的全部在交易永续合约。
2. 合约目录每日自动与币安官方列表同步，并支持手动同步。
3. 主体悬浮窗保持简洁，只常驻显示交易对、最新成交价、24 小时涨跌幅。
4. 支持用户自选、排序、滚动、调整可视行数和窗口尺寸。
5. 支持多周期、单币种阈值、阶梯式重复触发的异动提醒。
6. 支持系统代理、手动 HTTP/SOCKS5 代理、固定重连和可诊断日志。
7. 在默认 500ms 和最低 100ms 的界面刷新配置下保持有界内存和良好响应。
8. 作为公开 MIT 项目发布，便于社区审查和二次开发。

### 2.2 非目标

首版不包含：

- 交易下单、撤单、持仓、账户余额和 API Key 管理。
- 标记价格、指数价格或双价格常驻显示。
- K 线图、盘口、成交明细、资金费率、持仓量和多空比。
- 长期价格历史页面或复杂警示历史管理。
- 自动更新或版本检查。
- 遥测、行为分析和模拟行情兜底。
- Windows 7、macOS 和 Linux 支持。

## 4. 技术路线

### 4.1 技术栈

- 桌面框架：Tauri 2。
- 核心服务：Rust。
- 界面：TypeScript + 轻量前端组件方案。
- Windows 渲染：系统 WebView2。
- 持久化：`settings.json`、SQLite、Windows Credential Manager。
- 开源协议：MIT。

选择 Tauri 的原因：

- 相比 Electron 更轻，符合“体积和内存 ≈ Windows 原生体验 > 开发速度”的优先级。
- 能实现无边框、置顶、托盘、多窗口、窗口边界和系统启动集成。
- UI 仍可使用 HTML/CSS 实现精细布局与动画。
- Tauri 自身 MIT/Apache-2.0 许可证与本项目兼容。

### 4.2 模块边界

Rust 核心至少分为以下独立模块：

1. `contract_catalog`：双市场合约目录同步、过滤、差异和缓存。
2. `market_stream`：REST/WS 客户端、代理、订阅、重连和新鲜度。
3. `price_store`：最新价格、24h 涨跌幅、分钟采样和环形缓冲。
4. `alert_engine`：多周期计算、单币种阈值、冷静期、阶梯基准和过期。
5. `persistence`：JSON、SQLite、迁移、清理和原子保存。
6. `window_manager`：主体、设置、警示窗口、屏幕边界、锁定和动画协调。
7. `tray_autostart`：托盘与开机启动。
8. `logging`：错误归类、重复聚合、脱敏、保留和导出。

TypeScript UI 至少分为：

1. 主体悬浮窗。
2. 设置窗口。
3. 侧边异动警示窗口。
4. 可复用的固定列行情行、卡片堆、菜单和状态组件。

UI 不直接调用币安接口，也不自行计算异动。所有业务状态由 Rust 提供。

## 5. 数据源与行情处理

### 5.1 市场范围

支持：

- USDⓈ-M 永续合约，包括币安官方当前提供的 USDT、USDC 等结算资产。
- COIN-M 永续合约。

目录过滤条件：

- `contractType = PERPETUAL`
- `status = TRADING`

只使用币安官方公开 REST 和 WebSocket 接口，不需要 API Key。

### 5.2 合约目录同步

- 首次启动先读取最后一次成功缓存，避免阻塞主体出现。
- 上次成功同步距当前超过 24 小时时，在后台同步 USDⓈ-M 与 COIN-M 目录。
- “交易对管理”页面提供“立即同步”。
- 两市场分别校验和更新；一个市场失败不覆盖另一个市场的成功结果。
- 只有结构校验通过的响应才可替换缓存。
- 同步失败继续使用最后一次成功缓存。
- 新增合约进入可查询列表，但不自动加入主体自选。
- 已下架或不再交易的已选合约保留在主体，显示“已下架”，停止行情与警示，等待用户移除。

### 5.3 最新价格与 24h 涨跌幅

- 主价格必须是最新成交价。
- 最新价使用官方实时或 100ms 聚合成交流维护。
- 24h 涨跌幅使用官方单币种 ticker 的最新值。
- 不显示标记价格和指数价格。
- 价格格式依据官方合约精度信息，不使用固定小数位。

### 5.4 界面刷新周期

“基础设置”包含价格刷新周期：

- 默认值：500ms。
- 最小值：100ms。
- 最大值：2000ms。
- 允许输入范围内任意整数，不限制为 100ms 步进。
- 修改立即生效并持久化，不重建网络连接。

网络接收与 UI 刷新分离：

- Rust 持续接收和处理最新行情。
- UI 按设置间隔读取最新快照。
- 间隔内多次更新只保留最后值，禁止待渲染消息无界堆积。
- 没有新成交时价格保持不变。
- 异动引擎不受 UI 刷新周期影响。

## 6. 本地存储与内存策略

### 6.1 混合存储

#### settings.json

保存：

- 基础设置。
- 自选交易对和排序。
- 可视行数。
- 刷新周期。
- 异动全局配置和单币种配置。
- 主体隐藏时的警示策略。
- 窗口位置、尺寸、置顶和锁定状态。
- 代理模式及不含密码的代理配置。

只在设置变化时原子写入。

#### SQLite

保存：

- `state.db`：合约目录及同步元数据、最近约 1500 分钟的分钟价格采样、警示卡片、展示关闭状态、到期时间、上次触发价和冷静期。
- `logs.db`：聚合后的应用日志。日志单独存放，以便严格执行 7 天和 10MB 的清理上限。

使用事务、必要索引和版本化迁移。

#### Windows Credential Manager

保存手动代理的认证凭据。配置文件和日志不得出现明文密码或认证头。

### 6.2 内存数据

- 每个自选币对仅保留最新价格与最新 24h 涨跌幅。
- 每个启用警示的币对使用固定容量分钟环形缓冲。
- 不在内存中保存所有逐笔成交。
- 不一次性加载全部日志或警示卡片；按页面和当前卡堆查询。
- 分钟样本、UI 消息队列和窗口事件队列必须有固定上限。

### 6.3 自动清理

- 分钟样本固定保留约 1500 分钟，以覆盖 24h 基线并留出时间对齐余量。
- 警示卡片超过 6 小时后删除。
- 日志超过 7 天或 `logs.db` 逻辑记录总量超过 10MB 时，从最旧日志组开始删除；清理后按需执行 WAL checkpoint 和受控压缩，避免数据库文件长期虚增。
- 合约目录每日以校验后的最新快照替换，不保留无限历史版本。
- 数据库大小不得随运行天数持续线性增长。

### 6.4 启动预热

- 优先使用仍新鲜的本地分钟样本。
- 对缺失时间段按并发与官方限频约束补取公开 1m K 线。
- 某周期数据不足时只暂停该周期警示，不阻塞价格显示。
- 不补发应用关闭或断线期间的异动警示。

## 7. 主体悬浮窗

### 7.1 默认状态

- 默认自选：`BTCUSDT`、`ETHUSDT`、`SOLUSDT`。
- 默认可视行数：3。
- 可视行数范围：1–20。
- 默认开机启动：开启，可在设置中关闭。
- 默认始终置顶：开启，可通过右键菜单切换。

### 7.2 常驻信息

每行固定三列：

1. 交易对。
2. 最新成交价。
3. 24h 涨跌幅。

主体不显示“交易对 / 最新价 / 24H”视觉表头；字段语义由每行的可访问性标签保留。

主界面不常驻显示设置按钮、刷新按钮、标记价、警示周期或辅助说明。

### 7.3 布局行为

- 单窗口纵向列表。
- 超出可视行数后使用纵向滚动。
- 行高和三列结构固定，不因警示出现而改变；392–300px 压缩区间内连续收紧间距与字号。
- 最新价格不做闪烁动画，颜色固定跟随 24h 涨跌方向：正数绿色、负数红色、零值中性。
- 最新价与 24h 涨跌幅禁止省略或裁切；仅极端长交易对名称允许省略。
- 自选为空时显示简短提示，引导进入设置添加交易对。

### 7.4 窗口外观与交互

- 无 Windows 默认标题栏。
- 不显示最大化、最小化和关闭按钮。
- 空白区域用于拖动窗口。
- 四边和四角可拖动改变尺寸。
- 高度调整按完整行吸附，并同步更新可视行数。
- 主体最小宽度为 300px；最小高度为 66px，至少完整显示一行三列，禁止数字重叠或截断。
- 最大高度不得超出当前显示器可用工作区。
- 多显示器环境保存并恢复所在显示器与位置；显示器缺失时移动回当前可用工作区。

### 7.5 两级锁定

- “锁定大小”：禁止缩放，仍可移动。
- “锁定窗口”：同时禁止移动和缩放，并覆盖“锁定大小”。
- 锁定状态通过主体右键菜单切换并持久化。

### 7.6 主体右键菜单

至少包含：

- 始终置顶。
- 锁定大小。
- 锁定窗口。
- 设置。
- 隐藏到托盘。
- 退出。

退出前保存状态、有序关闭网络和数据库。

### 9.1 基础设置

- 开机自动启动：默认开启，可关闭。
- 始终置顶状态。
- 可视行数：默认 3，范围 1–20。
- 价格刷新周期：默认 500ms，范围 100–2000ms 任意整数。

采用双栏管理：

- 右侧：全部官方永续合约、模糊搜索、USDⓈ-M/COIN-M 筛选、添加。
- 顶部显示上次成功同步时间和“立即同步”。
- 新增交易对自动套用默认异动模板。

### 9.3 异动提醒

包含：

- 全局周期多选：5min、10min、1h、6h、12h、24h；默认开启 5min、10min、1h。
- 全局同向冷静期：固定 5min。
- 全局警示展示寿命：固定 6h。
- 默认单币种模板：警示开启、上涨 5%、下跌 5%。
- 每个自选交易对独立设置：警示开关、上涨阈值、下跌阈值。
- 主体隐藏时的行为：
  - 默认：主体继续隐藏，侧边警示在主体上次位置附近显示。
  - 可选：仅记录；重新显示主体后再进入侧边卡片堆。

### 9.4 网络代理

- 默认跟随 Windows 系统代理。
- 可切换为手动 HTTP 或 SOCKS5。
- 手动代理包含地址、端口和可选认证。
- 保存前提供连通性测试。
- 代理配置同时作用于 REST 和 WebSocket。
- 手动代理失败时不得静默回退直连。
- 保存新代理后有序重建网络客户端并恢复订阅。

### 9.5 日志

- 显示应用错误、警告和恢复信息。
- 支持按级别和来源筛选。
- 支持复制选中、导出和清空。
- 分页读取，避免全部日志加载到内存。
- 显示保留规则：最近 7 天、最大 10MB。

### 9.6 关于

- 应用名称、版本和 MIT 许可证。
- 项目开源属性。
- 第三方许可证入口。
- 只读公开行情和无交易功能说明。

## 10. 异动提醒业务规则

### 10.1 配置层级

全局配置：

- 启用周期：5min、10min、1h、6h、12h、24h，可同时启用。
- 同向冷静期：5min。
- 展示寿命：6h。
- 新增交易对默认模板。

单交易对配置：

- 警示开关。
- 上涨阈值。
- 下跌阈值。

同一交易对的阈值应用于全部已启用周期。

### 10.2 首次触发

对每个已启用警示的自选交易对，分别计算每个全局周期：

`涨跌幅 = (最新成交价 - 周期起点价格) / 周期起点价格 × 100%`

- 涨跌幅达到单币种上涨阈值，触发该周期上涨警示。
- 涨跌幅达到负向下跌阈值，触发该周期下跌警示。

警示记录至少包含：

- 市场。
- 交易对。
- 周期。
- 方向。
- 触发涨跌幅。
- 触发价格。
- 触发时间。
- 到期时间。
- 展示关闭状态。

### 10.3 冷静期隔离

冷静期按以下组合独立计算：

`market + symbol + period + direction`

同一组合触发后进入 5 分钟冷静期。冷静期内同方向继续移动不生成新警示。反方向和其他周期不受影响。

### 10.4 阶梯式重复触发

- 首次警示后保存该组合的触发价格。
- 5 分钟冷静期结束后，以上一次同方向警示触发价格为新基准。
- 相对该基准继续同方向移动达到单币种阈值时，再次生成警示。
- 新警示的触发价成为下一阶梯基准。
- 卡片 6 小时到期不会清除阶梯基准。
- 修改该币种阈值、关闭该币种警示或移除交易对时，清除该币种相关周期和方向的基准与冷静期。

### 10.5 多周期同时触发

一次行情更新可以同时触发多个周期。每个周期生成独立警示卡，并进入同一交易对的卡片堆。

## 11. 异动提醒视觉与交互

### 11.1 行内警示

- 不使用警告 emoji。
- 使用币种名称变色、行背景色和左侧色条。
- 不增加新的布局列，不改变行宽、列宽和窗口宽度。
- 若上涨和下跌警示同时有效，以最新触发方向决定当前行颜色。
- 只要该交易对存在未过期警示，行内状态持续存在。

### 11.2 侧边警示卡

标题包含：交易对、周期、方向。

正文只保留：

- 涨跌幅。
- 触发价格。
- 触发时间。

右上角提供关闭按钮。

关闭当前侧卡：

- 将该卡标记为已关闭展示。
- 不取消行内警示。
- 关闭状态跨重启保存。
- 卡堆内仍有其他未关闭卡时，显示下一张。

### 11.3 Peek Stack Carousel

行为遵循工作区中的 `警示卡片开发说明.md`，并以本说明书的精简字段和交互覆盖该参考文档中的冲突项：

- 同一交易对的卡片组成一个堆栈。
- 顶部卡完整显示，后方卡只露出边缘。
- 1 张不显示明显堆叠；2 张以上显示层级和 `1 / N` 数量。
- 不显示滚轮切换说明和左右箭头。
- 点击当前卡片循环切换堆内卡片。
- 切换不删除、不确认、不改变警示状态。
- 最新触发卡默认在顶部。

### 11.4 多交易对排列与屏幕边界

- 不同交易对卡堆按最新触发时间从上至下排列。
- 侧边警示识别主体靠近当前显示器左侧还是右侧。
- 主体靠左时向右展开，主体靠右时向左展开。
- 侧卡不得超出当前显示器可用工作区。
- 两个及以上卡堆且总高度超过主体上下界时，在主体高度范围内纵向滚动。

### 11.5 动画

- 卡片切换采用约 180–260ms 平滑位移与缩放。
- 主体增删行、排序、高度和警示状态变化使用平滑过渡。
- 价格数字保持固定位置，只做短暂颜色反馈。
- 动画不得妨碍读取、拖动和点击。
- 遵循系统“减少动态效果”；启用时使用即时或极短过渡。

## 12. 网络、重连与陈旧状态

### 12.1 连接划分

- USDⓈ-M 与 COIN-M 分别维护连接与状态。
- 只订阅主体自选列表中仍可交易的合约。
- 自选变化后动态更新订阅。
- 单币种关闭异动警示不会停止价格订阅，但停止该币种异动所需的历史维护和判断。

### 12.2 固定重连

- 网络连接失败后固定每 5 秒重试一次。
- USDⓈ-M、COIN-M、目录同步分别维护重试状态，互不阻塞。
- 恢复后重新订阅当前自选并补齐必要周期基线。

### 12.3 陈旧价格

- 连续 10 秒未收到某市场行情，该市场进入陈旧状态。
- 受影响行保留最后可信价格但降低透明度。
- 主体角落使用固定位置状态点，不改变三列布局。
- 陈旧期间暂停对应币种异动判断。
- 收到新数据并补齐基线后自动恢复。
- 一个市场断线不得影响另一个市场正常显示和判断。

### 12.4 首次无缓存失败

首次启动且无目录缓存、网络又失败时：

- 主体显示可恢复错误状态。
- 提供重试和进入代理设置的路径。
- 不生成模拟价格。

## 13. 日志设计

### 13.1 日志来源

记录：

- USDⓈ-M / COIN-M REST 和 WebSocket 错误与恢复。
- 合约目录同步错误与缓存回退。
- 代理测试和重连错误。
- SQLite、配置迁移和状态恢复错误。
- 关键窗口与托盘初始化错误。

### 13.2 连续重复错误聚合

错误指纹由来源、错误代码、脱敏后的规范化消息组成。

- 第一次错误写入“首次”记录。
- 第二次起不追加普通行，而是维护“最后一次”记录。
- 最后一次记录更新时间并显示 `×N`。
- `N` 表示该连续错误组的总发生次数，包含首次。
- 错误类型变化、成功恢复、应用退出后，当前重复组结束。
- 恢复成功单独写一条信息记录。

示例：

```text
10:00:00  COIN-M WebSocket 连接失败：连接超时
10:00:25  COIN-M WebSocket 连接失败：连接超时 ×6
10:00:30  COIN-M WebSocket 已恢复，正在恢复订阅
```

### 13.3 日志隐私与保留

- 代理密码、认证头和敏感查询参数不得入日志。
- 代理用户名只允许脱敏显示。
- 页面显示与导出使用相同脱敏结果。
- 保留最近 7 天且总量不超过 10MB。
- 任一上限触发时，从最旧完整日志组开始删除。

## 14. 性能预算

以下为首版目标，未达标时必须分析优化，不能删除已确认功能规避：

- 典型 Windows 10/11 设备从启动到显示本地缓存主体框架：不超过 2 秒。
- 20 个自选、默认 500ms、稳定 10 分钟后的目标内存：不超过 120MB。
- 默认 500ms、常见四核设备的长期平均 CPU 目标：不超过 2%。
- 不内置完整 WebView2 Runtime 时的安装包目标：不超过 25MB。
- 100 个自选、100ms、双市场连续行情运行 30 分钟：内存不得持续增长，窗口保持可操作。

首版不设置人为自选数量上限；资源随自选数量合理增长，但不得随运行时间无界增长。
